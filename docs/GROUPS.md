# 多设备同步组（0.6.3）

## 添加设备

1. 任意 Windows 或 Android 设备打开“同步组 → 创建同步组”。选择专用中转或 WebDAV，填写连接信息、组名。专用中转仅创建组时需要服务器管理码；WebDAV 使用可读写且能创建目录的专用账号。
2. 已有组直接点击“邀请设备”，保持邀请页面开启。
3. 新手机扫描邀请二维码；新电脑选择“加入同步组”，粘贴完整邀请，或填写同一服务器及 16 位配对码。WebDAV 手动配对还需填写同一目录、账号与应用密码。配对码显示为四组字符，邀请有效期五分钟。
4. 核对两端设备名及六位安全码，必须在两端分别点击“安全码一致，确认”。不一致时关闭并重新生成邀请。
5. 加入完成后，已有设备通过签名成员清单发现新成员，通常一分钟内建立其余连接。Windows 提供“刷新成员”；Android 打开同步组页可触发成员更新。发起邀请的设备加入完成后不承担其他成员的中转职责。

Windows → 手机、手机 → 手机使用同一套扫码；手机 → Windows、Windows → Windows 使用配对码或粘贴邀请。组内同步仍经过选定中转存储，无需设备之间公网直连。

文本和自动同步图片发往所有已开启的目标设备。同一签名设备通过多个组连接时合并发送并自动尝试备用连接；文件分享仍选择目标设备，仅接收方同意后上传内容。每个文件最多 100 MiB。

## 管理与升级

组最多 8 台活跃设备，保留最多 32 个历史设备身份；达到历史上限需创建新组。本机最多保存 4 个签名同步组，设备间最多 16 条内部通道。界面统一按组开关，已停用的成员通道可在成员详情中恢复。暂停全部同步同时暂停后台成员检查。

“移出”签名通知其他成员停止向该身份发送后续内容；“退出”移出本机。网络不可用时先在本机生效，稍后重试发布；关闭应用会停止重试。已退出可删除本机组记录；若通知未送达，请在其他设备移除它。退出或被移出的设备可以通过新的有效邀请、双向核对安全码重新加入；重新加入会得到新的签名入组批次，不会直接清除或复用旧的授权。

早期双设备配对保留为双设备组，不删除原认证或密钥；新增成员需要重新建组与身份验证。旧版客户端不能加入同步组；不要给多个安装复制同一份私有身份或运行状态。

## 中转升级

使用 WebDAV 无需升级中转。自托管服务需要新增 `/v2/groups`、`/v2/invitations` 路由；保持原有 `/v1` 路由、Authorization 请求头、HTTPS 和数据卷。将反代请求体上限设为至少 101 MiB，长文件传输可将超时设至十分钟。

源码构建：`docker compose -f deploy/compose.yaml up -d --build`。CasaOS 先在解压的源码目录执行 `docker build -f deploy/Dockerfile -t clipbridge-relay:0.6.3 .`，再将现有应用镜像更新为该标签，保留实际挂载、端口和数据卷。不要用示例文件覆盖真实配置。

健康检查 `/health` 应返回 `status: ok`；`/v1/setup/info` 应包含 `groups: 1`。旧专用配对接口继续保留。

## 协议与安全边界

每个安装生成独立 P-256 ECDSA 签名和 P-256 ECDH 协商身份。首次配对使用 Bouncy Castle J-PAKE（NIST 3072/SHA-256），配对码的前六个字符是公开邀请索引，后十个字符是秘密口令。服务器没有口令或验证散列。参与者 ID 在握手前承诺公钥、设备名与组信任锚；加密 Hello 揭示随机承诺值，并通过签名及 ECDH 证明持有私钥。六位安全码由握手密钥派生；两端确认后才发送加密入组授权。失败的邀请需要重新生成。

成员证书由已有成员签名，初始根证书经已确认的配对固定。每个成员仅写自己的完整签名清单，包含单调序号、授权证书与移出记录；清单经独立目录密钥加密，拒绝旧序号及相同序号的分叉。客户端并非仅信任服务器返回的设备 ID。

设备之间使用原生 ECDH 及按组、设备对分域的 HKDF-SHA256，分别派生 AES-GCM 内容密钥。附件采用原有流式分块加密后单对象上传；清单也加密。专用服务的组访问凭据仅允许存取密文，不是目录或内容密钥。受信设备去重和重放状态按签名公钥隔离，不与旧版仅设备 ID 的配置混合。

这是应用协议实现，尚未接受独立安全审计。成员撤销在其他设备收到通知后生效；服务器可延迟或拒绝通知。移出不会擦除该设备已获得的历史内容或密钥，也不会自动轮换共用存储凭据与目录密钥，因此仍可能访问存储或成员元数据。需要彻底撤销存储权限时，创建新组并更换专用账号/存储凭据，废弃旧组。没有消息级前向保密或双棘轮。详见根目录安全说明。

WebDAV 不强制服务端执行一次性领取或销毁，客户端校验五分钟有效期，使用条件创建和不可变握手槽检测并发冲突；仅在可信设备之间分享邀请。过期文件不等于服务器已删除，WebDAV 目录需自行清理。专用组对象有 2 GiB / 8192 个文件配额，已完成附件由客户端清理；不承诺服务器按时间自动清除组对象。

## 开发验证

`python tests/group_flow.py` 覆盖 .NET 三设备全互通、成员传播、单侧不入组、错误口令、篡改清单、成员移除、Java/.NET 双向邀请、Java 手机间配对、WebDAV 三设备及大于 JSON 上限的加密附件。需 .NET 10、Android Studio JBR、已解析的 Gradle 依赖和 JSON 测试依赖。

Android Provider、相册和通知检查仅在独立空配置模拟器运行；真实 LSPosed/HyperOS 的 Hook 与后台行为仍需用户测试。

## 0.6.1 兼容修复

新版 WebDAV 组使用 `clipbridge/groups/<group-id>/`，邀请使用 `clipbridge/invites/<locator>/`，避开服务商顶层目录长度限制。早期组缺少存储版本标记时继续使用 `clipbridge-groups/<group-id>/`，避免移动用户数据。已存在握手槽先读取并校验，一致重试不重复覆盖，不一致则中止。

Windows 配对页面将连接错误置于输入区上方，连接成功后收起表单直接显示进度、安全码和确认按钮；支持复制配对码及兼容 Unicode 分隔符。客户端显示认证、权限、过期和限频的具体提示，WebDAV 不再被统一提示更新专用中转。


## 0.6.2 成员与回传修复

重新加入时，新的成员证书包含随机入组批次及其前一证书摘要，必须由仍可信的另一成员签名。撤销记录绑定具体批次，因此旧退出消息不会再踢出重新加入的设备；创建者也可由其他活跃成员重新邀请。客户端恢复自己签名的历史发布序号，避免删除本机组记录后计数回退。组内所有设备应更新至 0.6.2 后使用重新加入功能。

Android 的具体组详情仅显示该组成员与邀请操作，不显示全局创建/加入/扫码入口。进入新的邀请会清除旧详情筛选，返回首页时立即刷新全部同步组。

收到的剪贴项不生成新的广播事件。Windows 写入来源/事件标记，并核验内容摘要；Android 使用全局接收抑制与 ClipBridge 标签。接收端不会再次写入与当前剪贴板相同的文本，避免重复历史记录；新复制且内容变化的本地文本仍可发送。明确的手动上传快捷键仍可按用户意图再次发送。

WebDAV 再次邀请时，已存在目录的非标准 MKCOL 响应通过深度零 PROPFIND 确认，不再直接当作网络失败。目录请求放宽读取超时；Windows 标签统一为 WebDAV账号、WebDAV密码，账号位于上方。
